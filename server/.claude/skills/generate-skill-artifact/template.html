The test

For every line: would the reader understand or act differently without it? If not, cut it.

  • Match the depth to what was asked. A true fact nobody asked for is still noise.
    • Point to a deeper topic in one line instead of writing a section on it.
  • Dense is not cryptic: a newcomer must understand it from the text alone. Over-compression fails like padding.

Bullets and examples

Every concept gets a concrete example.

WhyA rule without one is half-explained, and a name in backticks is not an example.

✗

It's important to note that, in order to avoid issues, you should basically validate input early.

✓

Validate input in the DTO, before it reaches the domain.

NoteMermaid only where it renders as a picture or a model reads it. A terminal, code comment or commit message shows the raw source: use ASCII there.

Code comments say why, not what.

✓

if (amount <= 0) return false; // fail early: the domain never sees an invalid amount

Cut and keep

Cut preamble, closers, repetition, filler and decoration. Keep decisions with their reason.

WhyThe reason is what a later reader can't re-derive; the rest they skip or already know.

Kind✗ Cut✓ Keep
Opening"Here's an overview of…"The conclusion first
Closing"Let me know if…", recapsStop at the last fact
Facts"various", "basically"Names, numbers, paths, file:line

Condensing existing text

  1. Extract the ideas, one line each.

  2. Drop what the reader knows and what repeats.

  3. Order by dependency; nest refinements under their parent.

  4. Write each idea once, as a bullet with its example.

  5. Check against the original.

    Every idea that changes understanding or action survived. Fix weak or wrong content found on the way: padding often hides it.
